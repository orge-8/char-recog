# 训练模式：从头训练 vs 增量训练

> 状态：**3 个种子 × 3 轮完成**（2026-10-26）。结论已定稿。
>
> 起因：插件默认增量训练（加载当前启用模型 + 只训新增/改标图片），也提供从头训练
> （ImageNet 底座 + 全部图片）。此前从没测过「库不断变大时，增量相对全量到底损失多少」，
> 也没测过这个损失是否值得为它付全量的时间成本。

## 1. 问题

两条路径在 `recog/model.py` 里的差异不止「用哪些数据」：

| 维度 | 从头训练（full） | 增量训练（incremental，默认） |
|---|---|---|
| 初始权重 | ImageNet MobileNetV3-Small 底座 | 当前启用模型 |
| 训练数据 | 全部图片 | 仅新增 / 标签已修改的图片 |
| 轮数 | 15 | 10 |
| backbone 解冻 | 第 4 轮起解冻最后 4 个 block | 第 1 轮起解冻 |
| 学习率 | 分类头 1e-3 / 3e-4，视觉层 1e-4 | 分类头 1e-4，视觉层 3e-5 |

要回答的是：**在「初次全量训练 → 之后逐轮追加图片」的真实序列里，增量路径是否会因为
「不再复习旧数据 + 低学习率」而落后于每轮全量重训，落后多少，是否值得一条产品规则。**

## 2. 方法

### 数据

素材沿用 `experiments-sample-size.md` / `experiments-axis.md` 的同一批池子
（`char-exp/pools.json` + `洛天依4`）：

| 池 | 来源 | 可用 | 本实验用量 |
|---|---|---:|---:|
| 平涂正例（洛天依） | `Desktop\Ori\` 下 `lty` `lty1` `洛天依` `洛天依1` `洛天依2` | 264 | 250 |
| 厚涂正例（同人插画） | `Desktop\洛天依4\` | 151 | 134 |
| 相似角色负例 | `Desktop\Ori\` 下 16 个子目录（`言和` + `新建文件夹 (2)`–`(11)` 等） | 920 | 615 |
| 异画风负例 | `Desktop\Thumb\` 下 7 个子目录 | 521 | 345 |

用量由**正例池上限**决定：初始 + 3 轮追加必须 ≤415，因此 240 + 3×48 = 384，留 31 余量。
初始库 840 张（160 平涂 + 80 厚涂 + 600 负例），每轮追加 168 张（+48 正 +120 负，
等于初始库的 20%）。三轮后库规模 840 → 1008 → 1176 → 1344（+60%）。

`pools.json` 里另有 24 张非角色照片（`C:\Windows\Web` 壁纸）本轮**未使用**：本次负例只取
「相似角色 + 异画风」两类。`Ori_neg_hard` / `Ori_yanhe_new` / `Thumb1` / `Thumb1_review` /
`洛天依4_review` 不在池内，未参与。入库走硬链接，桌面素材原文件未被移动或修改；
`洛天依4\Image_1751870303334.png`（25.7 MiB）被插件自身的 20 MiB 单张上限拒收。

### 序列与两臂

每个种子一个独立 store（独立 SQLite 与图库），运行顺序固定：

1. 基线：整个初始库做一次**全量训练** → 得到 M0，两臂共用。
2. 第 r 轮（r=1,2,3）：入库 168 张新图，然后
   - **full 臂**：从 ImageNet 底座重训整个库（15 轮）；
   - **incremental 臂**：加载该臂上一轮模型，只训本轮新图（10 轮、低学习率）。
3. 两臂共用同一数据库 ⇒ **同一划分、同一固定评估集、同一新批留出集**，逐轮配对比较。

直接调用插件真实代码：`Store.freeze()` 建快照（含 `_ensure_eval` 的固定评估集）、
`model.train()` 训练。未改任何超参、增广或两段式策略。

### 两把尺子

| 口径 | 集合 | 衡量什么 |
|---|---|---|
| ① 旧知识保持 | 固定评估集（基线时由 `_ensure_eval` 按 `(宽,高)` 整批选出，两臂都不训练） | 遗忘。掉分 = 旧分布上的能力退化 |
| ② 新数据吸收 | 每轮新图中落在插件自身 `test` 划分的 15%（两臂也都不训练，三轮累计 25/50/75 张） | 新素材有没有学进去 |

评估集 50 张（25 正 + 25 负）⇒ **1 张正例 = 4 点召回、2 点 balanced_accuracy**，这是全部
数字的读数下限。

### 判据（先写死再跑）

同一 (种子, 轮次) 上计算 `full − incremental` 的差值，跨种子取均值与标准差：
**|均值| ≥ 2×σ 且方向一致**才算真实差异；σ=0（各种子差值完全相同）判为**退化，不裁定**。

### 与生产的对应关系

- 生产 `seed_all()` 硬编码 42；实验按种子播种（42/43/44），否则种子间只有数据抽样差异、
  训练轨迹完全相同，σ 无从估计。生产行为不受影响。
- 实验给 `Store.ingest` 打了确定性 ID 补丁（种子 + 计数器）。原因是 `ingest` 用
  `uuid4().hex` 命名，而评估集选取与划分填充都按 group id 排序 ⇒ 随机 ID 会让同一个种子
  每次跑出不同划分。已验证：同种子两次运行指标逐位一致。

## 3. 结果

### 模型健康度（先看这个）

| seed | 基线 BA@0.60 | 基线 BA@0.50 | 划分（train/val/test/eval） |
|---|---:|---:|---|
| 42 | 0.760 | 0.740 | 551 / 118 / 118 / 50 |
| 43 | 0.860 | 0.860 | 554 / 118 / 118 / 50 |
| 44 | 0.760 | 0.800 | 553 / 118 / 118 / 50 |

三个种子的基线相差 10 点（0.760 / 0.860 / 0.760），而评估集只有 50 张 —— **种子级波动本身
就有这个量级**，这决定了后面能判读到什么程度。

## 4. 判读

**结论 1：准确性上，增量与全量无可检测差异。** 3 种子 × 3 轮 × 2 个阈值，评估集的
balanced_accuracy、精确率、召回与新批召回全部落在噪声内（|均值| ≤ 0.03，跨种子方向不稳定）。
唯一通过判据的准确性指标是**第 3 轮新批精确率（+0.080，三种子同向）**，即全量在新素材上
误报略少，但幅度约 1–2 张图，属于读数下限附近。

**结论 2：没有观察到灾难性遗忘。** 增量臂在固定评估集上围绕基线摆动，seed 44 上还持续
变好（+0.06 / +0.04 / +0.08）。机制与代码一致：增量只学新图、学习率压到 1e-4/3e-5，
等于在旧最优点附近小步走 —— 它既不冲掉旧知识，也不会崩。

**结论 3：2 个种子会给出假阳性，第 3 个种子把它翻了回来。** 只有 2 个种子时，
第 2 轮两臂差值恰好都是 +0.040（σ=0），判据把任意非零差判成「真实差异」；补上 seed 44
（−0.060）后，均值掉到 +0.007、σ 升到 0.058，判定改为噪声内。**这是本文最重要的一条方法学
结论**：n=2 时 2σ 规则在差值相近时会退化成「必判显著」，不能作为定案依据。

**结论 4：成本差 5–6 倍且随库增长扩大。** 这是本轮唯一量级明确、无需统计检验的一侧。

## 5. 效力边界

- **评估集 50 张，分辨率 2 点 BA**。所有 ≤4 点的差值都在读数噪声附近；本实验只能排除
  「10 点以上量级」的差距，不能证明「完全没有差距」（与 `experiments-axis.md` 的天花板问题同类）。
- **3 个种子的基线本身相差 10 点**（0.760 / 0.860 / 0.760）。种子级波动大于待检验效应，
  这是本实验最大的局限：要么加评估集，要么接受「只排除大效应」。
- **单角色（洛天依）、固定配比、固定追加节奏**（每轮 +20%）。换成「一次追加 100 张」或
  「只追加厚涂」结论可能不同 —— 增量对分布外新增的响应这次没测。
- **`test` 划分当留出集**：不是按 `(宽,高)` 整批隔离，新图与旧图可能同源，新批吸收的绝对值
  可能偏乐观。两臂共用同一留出集，配对比较不受影响。
- 全量臂每轮都从同一个 ImageNet 底座起步，**没有**测「在全量基础上继续微调」这种第三条路径。
- 第 3 轮新批精确率的 +0.080 虽通过判据，但只有三轮累计 75 张留出图，且与 0.50 阈值下的
  同项（+0.052，噪声内）不一致 —— 按「同一现象应在两个阈值上都在」的标准，它只能算**弱证据**。

## 6. 规则建议

由本轮数据能支持到的程度：

1. **默认保持增量训练。** 准确性无可检测差异，成本 1/5–1/6，且没有遗忘迹象。
2. **全量重训的提示应由报告信号触发，不用库规模触发。** 本轮库增长 60%（3 轮 × 20%）都没
   换来可检测的准确性差距，所以「库涨了 X% 就该全量」这种规模阈值在数据上站不住。可用的
   触发条件是：
   - 报告中评估集 `balanced_accuracy` 连续两次训练下降；
   - 新批精确率持续走低（本轮唯一同向的信号项）；
   - 新增图片明显换画风（增量不会重新校准旧分布）。
3. **不建议**「每次训练都全量」：5–6 倍时间换 ≤1–2 张图的差异，不成立。
4. **不建议**把「增量会遗忘」写进文档或提示文案：三轮 60% 增长后没测到，与
   `docs/experiments-axis.md`「厚涂 2% 是分布外而非画法」是同一类教训 —— 先有数据再写因果。
5. **若以后要重测这个问题**：先把评估集扩到 150–200 张并跨 `(宽,高)` 分批，否则 4 点以内的
   差异永远判不出来；种子数至少 3，且必须在判据里显式排除 σ=0。
