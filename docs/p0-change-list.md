# P0 改动清单 v2：内容类型（媒材单轴 + 固定评估集）

> 目标：训练报告能说出「**贴纸 91%，厚涂插画 72%，实拍没有样本**」，而不是一个混在一起的 79%。
>
> 不改训练算法、不改模型结构、不改阈值、不改推理链路。

## 实现状态（0.5.12）

**第 1–4 步已落地**，与本文的差异只有三处，都是实现时发现必须补的：

| 计划 | 实际 | 原因 |
|---|---|---|
| 评估集预算「每档 25 张」 | 追加「每类至少留 20 组给训练」 | 否则小库会被评估集抽空，`freeze` 直接报「不足 20 组」 |
| 批次整批归边 | 单批次超过预算时退化为批内抽样，并记 `unisolated` | 只有一批时无法既隔离又留够训练量，只能如实标注 |
| — | 稀有类型优先分配预算 | 否则一个 20 张的主导类型会吃光预算，最该被评估的小类型一张都进不去 |

未做：第 5 步（生成 100 张预填标注页）—— 需要你先确认聚类预填的准确性，否则会浪费你的标注时间。

## 0. 本轮定下的决策

| 项 | 结论 | 关键理由 |
|---|---|---|
| 轴的形态 | **单轴媒材 4 档** `flat / paint / photo / composite` | 只有这一轴有实测效应（同人插画 2% vs 贴纸 91%）；加来源轴无证据 |
| 老数据标注 | **抽样，每档 25 张**（`photo` 全标） | 全标 564 张对结论无额外信息 |
| 评估集 | **固定评估集**，用 `split='eval'` 标记，永不进训练 | 随机划分下每档只有 3–4 张 test，指标永远 `unreliable` |
| 同源隔离 | **批次（宽×高）整批归边**，同一批不跨训练/评估 | `洛天依4` 有 47/151 张同为 1242×1863，随机拆会虚高 |
| 负例 | 粗三档 `neg_type`：其他角色 / 非角色内容 / 表情包 | 误报率必须有负例分组；0.5.3 证明负例来源决定盲区 |
| 小数据降级 | **覆盖率保底**：不算指标也能说「训练集没有 X 类」 | 20 张时也成立，直接对应「该补什么」 |

## 1. 一条被证据推翻的旧结论（必须先改文档）

我此前写「官方立绘 79–91% 召回」。聚类抽样 264 张后：

| 簇占比 | 实际内容 | 归档 |
|---:|---|---|
| 71% | 2D 平涂 Q 版贴纸（荧光棒、猫耳、吃包子） | `flat` |
| 25% | 梗图/表情包（UFO + 大字） | `composite` |
| **3%** | 官方设定三视图 | `paint` |
| 0.4%（1 张） | 3D 渲染外景 | `flat` |

**官方立绘只有 3%（8/264）。** 所以：

- 「官方立绘 91%」应更正为「**Q 版贴纸 91%**」；
- 同人插画 2% 不是「二创 vs 官方」，是**训练集里几乎没有厚涂插画**；
- 「非角色照片 0% 误报」要加边界：**玩偶实拍是正例**，不能塞进非角色负例。

改动位置：`docs/experiments-sample-size.md` 第七之二、第十节、第十二节的相关表述。

## 2. 数据模型

### 2.1 新增两列

```sql
ALTER TABLE images ADD COLUMN style TEXT NOT NULL DEFAULT ''
ALTER TABLE images ADD COLUMN neg_type TEXT NOT NULL DEFAULT ''
```

| 列 | 取值 | 语义 |
|---|---|---|
| `style` | `flat` / `paint` / `photo` / `composite` / `''` | 任何图（正例负例都用），空 = 未标注 |
| `neg_type` | `other_character` / `non_character` / `''` | **仅当 label='other'**；身份轴，与形态轴（`style`）正交 |

`neg_type` 与 `style` 正交：一张「其他角色的厚涂插画」= `style=paint` + `neg_type=other_character`。

### 2.2 划分标记

不新增列，直接给 `groups.split` 增加第 4 个取值 **`eval`**：

| 取值 | 含义 | 行为 |
|---|---|---|
| `train` | 训练 | 现状 |
| `val` | 选轮 + 阈值建议 | 现状 |
| `test` | 全局指标 | 现状 |
| **`eval`** | **固定评估集** | 不进训练、不进 val、不参与随机 test 分配 |

复用现有列的好处：**老库零迁移**（所有行仍是 train/val/test，行为逐行不变）。

### 2.3 兼容性硬约束

`freeze()` 的分配循环只处理 `split IS NULL` 的行（`store.py:537`），因此 `eval` 行天然不被重新分配。需要改三处：

1. `targets` 与 `counts` 计算时排除 `eval` 行（否则 train 目标数会多算）；
2. 训练态文案映射加 `eval → 评估集`（`store.py:437`）；
3. `partitions` 只取 train/val/test，`eval` 行由 `evaluate()` 单独评估。

## 3. 评估集怎么建

### 3.1 批次（同源代理）

同一 `(width, height)` 视为同一批次。**这是廉价近似，不是真来源** —— 同一画师可能导出不同尺寸，但足以挡住「同一批 47 张同时进训练和评估」。

> 局限写进报告：批次 ≠ 画师，指标仍可能偏乐观。

### 3.2 算法

```
func build_eval(character, per_style=25, neg_per_kind=15):
    rows = 该角色所有已标注且 style != '' 的图
    for style in (flat, paint, photo, composite):
        批次 = 按 (width,height) 分组该 style 的正例
        打乱批次顺序
        逐个整批放进 eval，直到累计 >= per_style
    for neg_kind in (other_character, non_character, sticker):
        同样按批次取，直到 >= neg_per_kind
    if 某档总数 < per_style: 全进 eval（报告显示「样本不足」）
    写入 groups.split='eval'
```

整批归边是硬规则：一个批次要么全 eval、要么全训练，**不许拆**。

### 3.3 触发方式

- 首次训练时若该角色没有 `eval` 行 → **自动建一次并锁定**（写入 `settings["eval_built:<character>"]`）；
- UI 提供「重建评估集」按钮（二次确认），重建后报告标注「评估集已变更，与历史不可比」。

### 3.4 为什么固定

| 好处 | 说明 |
|---|---|
| 指标可算 | 每档 25 张评估样本，不再受 15% 划分比例压制 |
| 跨版本可比 | 同一批图评同一批图，`comparable_to_previous` 不再因新图加入变成 False |
| 不污染选轮 | `eval` 只用于最终报告，`val` 仍从训练池随机切 |

## 4. 报告

### 4.1 三块输出

```json
{
  "coverage": [{"style":"flat","label":"平涂/Q版","train":163,"eval":25,"verdict":"covered"},
               {"style":"paint","label":"厚涂插画","train":98,"eval":47,"verdict":"covered"},
               {"style":"photo","label":"实拍","train":0,"eval":0,"verdict":"missing"}],
  "styles":   [{"style":"flat","n":25,"recall":0.92,"unreliable":false},
               {"style":"paint","n":47,"recall":0.72,"unreliable":false}],
  "advice":   "训练集没有「实拍」类图；「厚涂插画」召回 72%，比「平涂/Q版」低 20 个百分点，建议再补 30 张"
}
```

- `coverage`：**永远输出**，20 张时也成立 —— 这就是「B 保底」；
- `styles`：只在 `n >= 5` 时给百分比，否则 `unreliable: true` 且 UI 不显示数字；
- `advice`：优先级 = 完全缺失的档 > 召回最低且 n≥5 的档。

### 4.2 文案纪律

- 必须点名**哪一档、差多少、补几张**，不写「需要更多数据」这类空话；
- `photo` 档只有 3 张时写「样本不足（n=3）」，绝不写 0%；
- 报告头注明「评估集与训练集已按批次隔离 / 未隔离」。

| 文件 | 用例 | 断言 |
|---|---|---|
| `tests/test_eval_set.py`（新） | 同批次 10 张 + 其他批次 40 张 | 该批次 10 张全在 eval 或全在 train，绝不跨边 |

## 7. 验收

1. 用 4 档各 25 张（`paint` 用 47 张那批）建评估集，跑一次从头训练，报告出「覆盖矩阵 + 分档召回」；
2. `paint` 档召回 ≥ 60%（比 0.5.8 的 82% 下调：那次同源拆分虚高，这次批次隔离后应当更低）；
3. `photo` 档显示「样本不足」，不显示 0%；
4. 老库迁移后 split 与 0.5.9 逐行一致；
5. 同一库连续跑两次训练，评估集成员完全相同。

## 8. 风险

| 风险 | 处理 |
|---|---|
| 批次代理不准（同画师不同尺寸） | 报告注明「批次隔离 ≠ 画师隔离」，指标仍可能偏乐观 |
| 47 张那批全进 eval → `paint` 训练只剩 98 张 | 可接受；若召回明显下滑，说明该批画风本身特殊 |
| 管理员不标 style | 全部 `''`，`coverage` 显示「全部未标注」，其余功能照常 |
| 重建评估集导致历史不可比 | 报告显式标注，按钮二次确认 |
| eval 集被拿去调阈值 | 代码上 eval 不参与 `suggest_threshold`（只喂 val），有测试钉住 |

## 9. 不做

- 不加来源轴（官方/二创）—— 无证据表明它造成召回差异；
- 不自动推断 style —— 模型在陌生画风上 66% 误报，推断必错；
- 不做共享骨干 / 度量学习（P1）；
- 不做切块推理（P2）；
- 不因 style 改变训练采样数量（P0 只分组，不改训练）。
