# 训练模式决策记录（char-recog）：从头训练 vs 增量训练

> 主题：默认增量训练（加载启用模型 + 只训新增/改标图片）相对全量重训（ImageNet 底座 + 全部数据），
> 在多轮追加的真实使用序列下对准确性有什么影响。
> 本文件是研究过程的决策留痕，结论落点见「已确定」D2。

## 背景（事实，来自代码与文档，非决策）

两条训练路径已在 `recog/model.py` 实装，差异不止「用哪些数据」：

| 维度 | 从头训练（full） | 增量训练（incremental，当前默认） |
|---|---|---|
| 初始权重 | ImageNet MobileNetV3-Small 底座 | 当前启用模型 |
| 训练数据 | 全部图片 | 仅新增 / 标签已修改的图片 |
| 轮数 | 15 | 10 |
| backbone 解冻 | 第 4 轮起解冻最后 4 个 block | 第 1 轮起解冻 |
| 学习率 | 分类头 1e-3 / 3e-4，视觉层 1e-4 | 分类头 1e-4，视觉层 3e-5 |

现成基建：`docs/experiments-sample-size.md` 的受控实验范式（直接调 `Store.freeze()` + `model.train()`、
固定测试集配对比较、多种子）；`docs/experiments-axis.md` 已验证「训练集没见过某类数据 → 该类召回崩掉」
的分布外效应；评估集（`(宽,高)` 整批划出、跨版本固定）是现成的跨版本可比指标基座。

因此研究问题实质是：**增量路径（低 LR + 少数据 + 少轮数）在反复追加图片的场景下，相对全量重训
损失多少准确性，损失是否落在噪声内，以及耗时差是否足以支撑一条产品规则。**

## 已确定

| # | 结论 | 理由 |
|---|------|------|
| D1 | 追问强度 = 细问（3/5 档），并留本决策记录 | 结论大概率触及「何时该全量重训」的产品规则，前提需钉死；但默认模式本身属工程取舍，不必证伪 |
| D2 | 研究落点 = **C 定规则**：产出「何时增量、何时该全量重训」的产品判据；若数据显示任何增量都显著掉分，B（改默认）升级为中间结论 | 无论数据指向哪边规则都能落进产品，且与 README 中「训练页按图组数给档位与建议」的既有交互一致；改默认属行为变更，需另走真机验证 |
| D3 | 取证方式 = **A 本地受控实验**（复刻 sample-size 范式） | 要的是因果（增量 vs 全量）；生产历史里每轮新增量、分布漂移不可控，只能得相关性 |
| D4 | 执行环境 = 已有 managed venv `char-recog-py312`（torch 2.14.1+cpu / torchvision 0.29.1+cpu，无 CUDA）；不新装、不下载 | 已实测导入成功；CPU 下单次训练约 5–8 分钟（667 样本 / 443 秒的历史数据），12 次 ≈ 1.5–2 小时 |
| D5 | 实验对象 = 单角色（洛天依），沿用 207 正 + 128 厚涂 + 800 负的已验证配比 | 与 `experiments-axis.md` 第二轮一致，该配比已训出健康模型（test balanced_accuracy 0.939），换配比会把「比例效应」混进「模式效应」 |
| D6 | 度量口径 = **双口径**：① 固定评估集（首轮由 `Store._ensure_eval` 选出，两臂都不训练）= 旧知识保持；② 每轮新图落在插件自身 `test` 划分的部分 = 新数据吸收 | 聚合指标会掩盖遗忘：增量可能在新图上涨分、旧图上掉分，净值为零。拆分后两侧证据同时可见 |
| D7 | 交付物 = **只出研究产物**（实验文档 + 规则建议文本 + 本决策记录定稿），不改代码 | 规则阈值必须由本次数据定出来，先实装等于硬编码未经测量的数字；行为变更应与真机验证绑定，不和研究混在一个 commit |
| D8 | 种子数 = 2（42 / 43）；关键差值落在判据边界（1–2 倍标准差之间）时再补第 3 个种子 | 沿用 `experiments-sample-size.md` 范式；2 个种子估出的 σ 本身不稳，只在需要裁定时付第三个种子的成本 |
| D9 | 初始库 840 张（160 平涂正例 + 80 厚涂 + 600 负例），每轮追加 168 张（+48 正 +120 负，≈初始库 20%） | **正例池上限决定**：可用正例 264 平涂 + 151 厚涂 = 415，初始 + 3 轮须 ≤415 → 240 + 3×48 = 384。原拟「207+128+800 初始、+20% 每轮」需 3 轮补 200 正例，池子不够 |
| D10 | 新批留出直接用插件自身 `test` 划分（15%），不额外切 10% | 效果等价（两臂都不训练）且少一次划分手术：改 `split='eval'` 有把「新变体并入旧组」的整组拖进评估集的风险，污染固定评估集 |
| D11 | 训练前把 `recog.model.seed_all` 换成按种子播种，生产仍是固定 42 | `seed_all()` 硬编码 42，不换的话「2 个种子」只换来相同训练轨迹，σ 无从估计 |
| D12 | 实验前给 `Store.ingest` 的图像 ID 打确定性补丁（种子 + 计数器），不改插件源码 | `ingest` 用 `uuid4().hex` 命名，而评估集选取与划分填充都按 group id 排序 ⇒ 随机 ID 会让同一个种子每次跑出不同的划分。已验证同种子两次运行指标逐位一致 |
| D13 | **实验结果：准确性上增量与全量无可检测差异**（3 种子 × 3 轮 × 2 阈值，评估集 BA/精确率/召回、新批召回全部落在噪声内）；唯一通过判据的是第 3 轮新批精确率 +0.080（三种子同向，但幅度约 1–2 张图，且 0.50 阈值下不成立，只算弱证据）；**成本 5–6 倍且随库增长扩大**（全量 311→584s，增量 69→102s） | 判据按 §5 预登记执行，未事后改口径。详见 `docs/experiments-training-mode.md` |
| D14 | **规则落地：默认保持增量；全量重训的提示由报告信号触发（评估集 BA 连续两次下降 / 新批精确率持续走低 / 新增图明显换画风），不用库规模阈值** | 本轮库增长 60% 都没换来可检测的准确性差距，「涨 X% 就该全量」在数据上站不住；信号驱动的提示只在该出现的时候出现 |
| D15 | 方法学修正：n=2 时「≥2σ」判据在种子差值相近时退化为「必判显著」。本次实测第 2 轮两臂差值都为 +0.040（σ=0），判据判成真实差异，补第 3 个种子（−0.060）后翻为噪声内。**同类实验种子数 ≥3，并在判据里显式排除 σ=0** | 这是本轮最贵的一课：不补第三个种子，报告里会写下一个假阳性结论 |

## 实验实现（供复核）

脚本 `char-exp/tools/mode_compare.py`（实验夹，不进插件仓库），直接调用插件真实
`Store.freeze()` + `model.train()`，未改任何训练超参或增广策略：

- 每种子独立 store 目录；共享一个基线全量模型，之后每轮同时跑 `full`（从头训练）
  与 `incremental`（加载该臂上一轮模型，只训新图）两臂
- 两臂共用同一数据库 ⇒ 同一划分、同一固定评估集、同一新批留出集，配对比较
- 判据：同一 (种子, 轮次) 上两臂的 balanced_accuracy / 精确率 / 召回差值，
  需 ≥2× 跨种子标准差且方向一致；另记训练耗时差
