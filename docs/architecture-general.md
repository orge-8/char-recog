# 通用角色识别插件的架构方案

> **历史文档（0.4.x 时期的设计稿）。** 文中「按内容类型分组 / 分层抽样 / 负例两类」的
> 标注方案在 **0.6.0 已被移除**：这些字段只喂分档报表，而标签本身不可靠（同一张图隔周
> 会标成不同档），聚合不可靠标签等于把噪声当诊断。当前实现见 README 的「图片与标注」与
> CHANGELOG 0.6.0。保留本文是为了留住当时的数据与推理，不是现状说明。

面向的部署形态：**5–20 个角色、持续新增**，单张图 2–4 秒预算，管理员愿意标注但希望省力，
自动提示与按需识别做成开关。

## 一、先说结论

这个插件的难点不在「模型准不准」，而在**你不知道会被喂什么图**。同一个模型、同一个角色：

| 内容类型 | 召回 |
|---|---:|
| 官方立绘 | 79–91% |
| Q 版贴纸 / 表情包 | ~68% |
| 同人插画（未加训） | 2–8% |
| 同人插画（加入 90 张同类训练） | **82%** |

差 40 倍，而模型、阈值、样本量都没变 —— 变的只是训练集有没有覆盖那种画法。
所以方案的重心是**让插件测出分布差距并告诉管理员补什么**，而不是继续调模型。

## 二、已验证的事实（可以直接作为设计约束）

1. **正例要覆盖实际分布**：只训官方立绘，同人图召回 2%；补 90 张同人图后 82%，误报只涨 5 个点。
2. **负例必须两类都有**：只用表情包当负例，模型对其他角色图的误报飙到 40.2%；混合后 1.4%。
3. **样本量是次要矛盾**：正例 20→200（10 倍）让精确率 0.521→0.843，远小于分布错配的效应。
   正负比 1:4 优于 1:1，且在两角色上复现。
4. **冻结 ImageNet 特征不足以识身份**：AUC 恒定在 0.78，加样本不涨（N=5/10/20/50 都一样）。
   ⇒ 「不训练、只算原型」的冷启动方案**不可行**。
5. **多命中靠 top-1 + margin 0.02 处理**；margin 0.08 会丢掉 4.6% 的正确命中。
6. **多角色图对每个角色都是正例**，但不能当另一角色的负例（否则教模型「这是 A → 不是 A」）。

## 三、架构：共享度量学习骨干 + 每角色轻量头

```
                    ┌───────────────┐
  图片 ──► 预处理 ──►│ 共享骨干(CNN) │──► 嵌入向量 ──┬──► 角色 A 头 ──► 分数 A
                    └───────────────┘              ├──► 角色 B 头 ──► 分数 B
                           ▲                       └──► 角色 C 头 ──► 分数 C
                           │
                  多角色联合训练（分类 + 度量损失）
```

**冷启动路径**（新角色，5–20 张）：
不再从头训 CNN，而是在已训练好的嵌入空间里算该角色的**原型/线性头**（几秒）。

**为什么要先做度量学习**：第二节第 4 条已证明，未训练的 ImageNet 特征不编码身份。
只有在多角色联合训练后，嵌入空间才具备「同角色靠近、异角色远离」的性质，原型头才有意义。

**风险与判据**：这是一条**尚未验证**的假设。验收判据是「新角色 10–20 张图，原型头达到
现方案 N=50 的水平（AUC ≥0.86、精确率 ≥0.64）」。达不到就不切架构，继续用现有从头训方案。

## 四、五个组件

### 1. 数据：按内容类型分组

上传时让管理员给每张图选一个**内容类型**（官方立绘 / 贴纸表情包 / 同人图 / 群聊截图），
而不是只标「是不是该角色」。这一步是整个方案的地基 —— 没有它就无法知道「哪类没覆盖」。

- 正例：`(角色, 内容类型)` 两层标签。
- 负例：`其他角色` 与 `表情包` 两类分开记。

**省力做法**：类型可以自动推荐（用嵌入向量聚类 + 现有模型分数），管理员只做确认。

### 2. 训练：分层抽样 + 负例两类

- **分层抽样**：按 `(角色, 内容类型)` 分层，保证每类都进训练集。缺哪类就在报告里点名。
- **负例组合**：其他角色图 + 表情包图，比例默认 1:4（已复现的最优档）。
- **负例共享（带防护）**：可借用实例内其他角色的图，但必须
  ① 排除与目标库 phash ≤4 重复；② 排除已知含多角色的库；③ 只用目标模型 <0.3 的；
  ④ 借到负例:正例 = 2:1 为止，报告注明借了多少。
  > 注意 ③ 在画风未覆盖时会筛错方向（实测言和模型对洛天依同人图打 66% ≥0.6），
  > 所以在画风覆盖达标前，共享负例只做「同类型内共享」。

### 3. 度量：真实流量验证回路（最关键的一环）

训练完成后，**必须**在一个「真实群聊图」样本上出报告，而不是只看测试集：

| 报告项 | 含义 |
|---|---|
| 分类型召回 | 「同人图 82%、贴纸 68%、海报 12%」 |
| 分类型精确率 | 每类误报多少 |
| 最差类型 | 直接提示「海报类只有 12%，建议补 30 张」 |

**实现方式**：管理员定期上传 50–100 张群图（插件先用现有模型筛出可疑的，只让他确认几十张 ——
这条流程已在实验里跑通，129 张标注约几分钟）。

**为什么非做不可**：我们两次估计「群聊图召回」，得到 6.6% 和 68.4% —— 差别全在分母
（这批图里真实有多少张含该角色）。没有带标签的真实样本，任何召回数字都不可信。

### 4. 策略：双阈值 + 开关

| 模式 | 阈值 | 多命中 | 用在 |
|---|---|---|---|
| **自动模式**（Hook 读群图） | 高（目标精确率 ≥0.9） | 只报 top-1，margin 0.02 内视为平手不报 | 默认关，误报代价高 |
| **按需模式**（`/识别` 或回复图） | 低 | 报 top-3，各自的分数与阈值都列出 | 用户主动要求，漏报代价高 |

同一个模型，两套阈值；配置里一个开关切换。

### 5. 交付：素材包与反馈闭环

- 每个角色给一个「补训包」样例：分目录的已标注图 + README（本次已产出洛天依的，469MB / 320 张）。
- 训练报告末尾固定两句话：**哪类最差**、**下一批该补什么**。

## 五、路线图

| 阶段 | 内容 | 验收判据 | 成本 |
|---|---|---|---|
| **P0** | 分层抽样 + 负例两类 + 真实群图验证报告 + 双阈值开关 | 报告能说出「哪类最差」；两套阈值行为可切 | 中（改 freeze、报告、UI） |
| **P1** | 多角色联合度量学习骨干，验证原型头冷启动 | 新角色 10–20 张达到现方案 N=50 水平 | 高（训练管线重写） |
| **P2** | 2×2 切块推理（可选开启） | 误报 19.2%→7.7%，召回不变 | 低（推理侧 4 倍耗时） |

**P0 不依赖架构变更，且是 P1 的判断依据**（P0 的验证回路才能告诉你 P1 值不值得做）。

## 六、明确不做的

- **不做「冻结 ImageNet 特征 + 原型」**：实测 AUC 0.78 恒定，加样本不涨。
- **不做全局统一阈值**：不同角色的最难负例不同，洛天依 N=20 精确率 0.521、言和 0.800，
  同一个阈值会把一边压死。
- **不用「目标模型分数」当负例筛选器**（画风未覆盖时会筛反）—— 除非已确认画风覆盖达标。
