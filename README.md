# 角色识别（char-recog）

管理员上传并标注角色图片，为**每个角色训练一个二分类小模型**（"是/不是该角色"）。插件自动识别收到的图片和表情，命中时在对应图片后添加上下文提示；同时提供只读工具 `recognize_character_image`。角色名单在插件配置 `characters` 中维护（默认预置中V主要角色，可任意增删）。

本插件是 [SengokuCola/MaiSelfPlugin](https://github.com/SengokuCola/MaiSelfPlugin)（GPL-3.0）的泛化改造版：把"是否包含 Bot 自己"的单角色二分类，泛化为**每角色一个二分类模型**的通用角色识别。训练、版本管理、依赖覆盖层等工程链路与上游一致；与上游的具体差异见文末「与上游的差异」。

- 插件 ID：`org.civetc.char-recog`
- 数据目录：由宿主 SDK 授予（`ctx.paths.data_dir`，默认 `data/plugins/org.civetc.char-recog/`）
- 插件目录名可以自取（宿主按 `_manifest.json` 识别），本文档示例用 `plugins/char-recog`

---

## 安装

需要 MaiBot **1.3.6 – 1.3.x**、SDK **2.11.0 – 2.13.x**（已在宿主 1.3.6/1.3.7、SDK 2.11.0/2.13.0 上验证），以及支持 `custom_pages`、`image_upload` 的 WebUI。超出该范围的宿主会拒绝加载；若你已在更新的版本上跑通，可自行放宽 `_manifest.json` 的 `max_version`。

1. 把插件目录放入 `plugins/`（例如 `plugins/char-recog`）。
2. 完整重启 MaiBot（热重载对含 manifest 的插件不生效）。
3. 在 WebUI 插件管理页启用，出现「**角色识别**」工作区。
4. 首次加载由宿主生成 `config.toml`；角色名单通过 `characters` 配置（默认预置中V主要角色）。
5. 插件附带通用预训练底座，角色模型需要管理员自行训练（见「训练与模型」）。

用本地 SDK 开发源码调试主程序时：

```powershell
$env:MAIBOT_PLUGIN_SDK_PATH = (Resolve-Path ../maibot-plugin-sdk).Path
$env:MAIBOT_WEBUI_USE_LOCAL_DASHBOARD = '1'
uv run bot.py
```

（使用本地 WebUI 前先在 `dashboard` 目录执行 `npm run build`。已发布版本无需这两步。）

## 运行环境

默认使用 MaiBot 的 Python，插件依赖安装在自己的覆盖层 `dependencies/packages`（位于插件数据目录内）。训练和推理优先加载覆盖层，其余包继承主环境。安装和卸载仅修改覆盖层，**不改动 MaiBot 主环境**。

自定义环境使用已有的 Python 解释器或环境目录，依赖由管理员管理。页面选择会持久保存，并优先于配置中的 `worker_python`；该配置留空时使用 MaiBot Python。更换底层 Python 大版本后需重新安装覆盖层。**被指定的解释器会以该路径执行插件的训练与推理代码**，请只指向可信环境。

GPU 版 PyTorch 默认选择 CUDA，也可选择 CPU；CPU 版使用 CPU；识别推理固定用 CPU。训练或推理运行期间锁定依赖操作，安装期间锁定工作进程启动。

安装先在临时目录完成，再核验导入路径、版本和 CUDA 运算，成功后切换到覆盖层，失败时保留原层。GPU 主包约 2.7GB，torchvision、配套依赖及解压文件需要额外空间。

下载进度、安装阶段和日志保存在插件数据目录。重载插件或重启 MaiBot 后，继续读取存活安装进程的进度，或恢复中断任务。下载支持断点续传；服务器拒绝续传或文件校验失败时重新下载，残留安装目录清理后重新安装。失败任务可手动重试。

停止推理后，通过手动开启或重新加载插件恢复。重载页面仅更新页面文件。

推理进程**超时或崩溃不再永久关闭自动识别**：首先熔断 30 秒，之后由后台自动重启；连续失败按 30/60/120/300 秒退避。第一条消息的冷启动（`import torch`）由后台预热线程完成，不占用下文的单条消息预算。手动停止是唯一粘性状态，只有手动开启或重载插件能解除。

## 依赖模型

这台机器上依赖分三层，出问题时先确认自己在哪一层：

| 层 | 内容 | 谁负责 | 位置 |
|---|---|---|---|
| 宿主环境 | `Pillow`、`numpy` | MaiBot 自身依赖（`_manifest.json` 的 `dependencies` 会校验版本） | MaiBot 的 Python |
| 插件覆盖层 | `torch`、`torchvision`、`Pillow`、`numpy`、`psutil` | 在 WebUI「运行环境」页点安装，插件自己下载并装入 | `<数据目录>/dependencies/packages/` |
| 自定义环境 | 同上，全部 | 管理员自行准备 | 管理员指定的解释器/环境 |

- **宿主环境**只装插件加载链路真正需要的东西：`recog/images.py` 顶层 `from PIL import Image`，`numpy` 在指纹计算时懒加载。这两个包在 `_manifest.json` 的 `dependencies` 里声明为 `Pillow >=11,<13`、`numpy >=2,<3`；宿主版本不满足时会拒绝加载。
- **插件覆盖层**里的 `torch`/`torchvision`/`psutil` 不写进 `dependencies`：体积太大（GPU 版约 2.7GB），不该让宿主预装。`psutil` 只在训练 worker 里用于采样峰值内存。
- **自定义环境**模式下插件不会安装任何东西，`torch`、`torchvision`、`psutil`、`Pillow`、`numpy` 必须已经存在；缺包时页面会提示「未安装 xxx」。
- 安装依赖需要 `uv` 在 PATH 中，并且能访问 `download.pytorch.org`（见「数据流向与网络访问」）。没有 `uv` 会明确报错，不会静默降级。

## 图片与标注

上传时为本批图片选择"是/不是该角色"。图片库支持修改标签、跨页批量操作、删除和恢复；「删除全部」**仅删除当前角色**的未删除图片，其他角色与已训练模型不受影响。历史训练任务引用的原图会保留。

支持 JPEG、PNG 和静态 WebP（GIF/动图和其它格式会被拒绝，拒收时会报出实际探测到的格式与帧数——扩展名不可信，实测有大量 `.jpg` 其实是动图 GIF）。宿主按页面声明的 `image_max_edge: 4000` 把上传副本等比缩放到 4000 像素以内；插件侧再校验单张 **20 MiB / 4000 万像素**上限。

JPEG 解码走 libjpeg 的缩尺解码（`Image.draft`）：训练时按该任务的输入尺寸解，推理时按最大的 448 解，省掉全尺寸 IDCT 与大图缩放。这对识别结果没有增益，只是更快——一张 12MP 图的预处理从约 300 ms 降到约 25 ms，训练每张约快 2.3 倍。非 JPEG 格式自动回退到完整解码；入库指纹与查重仍按**原始尺寸**计算，不受影响。

- 每批最多选择 100 个文件。
- 每页最多 24 张，单次批量操作最多 1000 张。查看范围可按内容类型与文字标记筛选，「未标注类型」视图专门列出还没标类型的图。
- 识别测试里判错的图可以直接「标为是/不是并入库」，不必先去图片库重新上传。

每张图可以标一个**内容类型**（平涂/Q版、厚涂插画、实拍），负例还可以标「它是什么」（其他角色 / 非角色内容）。两个字段回答两个不同的问题：内容类型是**形态**（这张图怎么画的），负例分档是**身份**（图里是别的角色，还是根本不是角色）。所以「其他角色的表情包」= 内容类型「平涂/Q版」+ 文字标记「有文字」+ 负例分档「其他角色」，三个字段各答一个问题，不再需要二选一。类型按批标注即可 —— 一次上传通常就是同一种来源。它的用途只有一个：让训练报告能分档告诉你「哪一类认不出」。不标也能正常训练，只是报告里只会给出整体指标。

相同文件或像素完全一致的图片复用已有记录和标签。近重复图片按变体分组，每组保留一个训练代表。查重在上传后进行，管理员可核对排除原因和标签冲突。

## 训练与模型

每类至少需要 **20 个独立图组**才能开始训练，但**这只是下限，不是建议值**。受控实验（真实插画，见 [docs/experiments-sample-size.md](docs/experiments-sample-size.md)）在 0.60 判定阈值下测得：

| 每类正例 | 50 | 100 | 200 |
|---|---:|---:|---:|
| 精确率（提示里正确的比例） | 0.64 | 0.66 | 0.84 |

20 组时精确率只有 0.52 —— **约一半的提示是错的**。更省力的替代是加负例：50 组正例配 200 组「不是该角色」的图片，精确率就能到 0.80，比把正例堆到 100 组更好。训练页会按当前图组数给出档位与建议。

样本量不是唯一的决定因素。同一批数据里，**厚涂同人插画**的召回曾只有 2%，把它标进训练后升到 82% —— 差距来自「训练集有没有见过这种画法」，而不是数量。因此报告除了整体指标，还会按内容类型分档给出召回与误报；某档样本少于 5 张时显示「样本不足」而不是 0%，避免用噪声做决定。

另有一个**文字叠加**标记（有字 / 无字），它和画法无关：贴纸、海报、梗图都可能带字，所以不占画法档位。

报告里是三张独立的表：**按内容类型**（画法：平涂 / 厚涂 / 实拍）、**文字叠加**（有字 / 无字，标记而非分档，因此同一批图会在两张表里各出现一次）和**按负例分档**（身份：其他角色 / 非角色内容）。它们回答两个不同的问题 —— 「哪一类图认不出」和「被认错的是不是别的角色」，所以不合并，也不互相替代。

分档指标跑在**固定评估集**上：首次训练时从已标注类型的图里按 `(类型, 宽, 高)` 整批挑出，之后每次训练都用同一批（同一批不会跨训练与评估，避免同源图虚高）。评估集不参与训练与选轮，重建它会让历史报告不再可比，训练页有显式的「重建评估集」按钮。**已有训练历史的库不会自动建**（那会改动既有划分），升级后需要点一次「重建评估集」；按钮的确认框会先告诉你它会占走多少张、分别来自训练/验证/测试集。

图片自动分为训练、验证和测试集。后续图片保持已有划分；同图变体跟随原组，连接不同划分的图片暂时排除。

新任务的增广包含颜色抖动、随机裁剪（保留 60%–100% 面积）与水平翻转；0.5.0 之前创建后又暂停的任务保持原增广（只做颜色抖动），以免恢复时输入序列突变。

默认增量训练：加载当前启用模型，仅训练新增或标签已修改的图片。模型保存累计训练来源，图片库显示当前模型是否训练过该图片。首次训练和从头训练使用通用预训练底座（ImageNet MobileNetV3-Small，SHA256 见 `recog/model.py` 的 `BASE_SHA`）。

每个实例同时运行一个训练任务。任务开始时冻结数据和标签，训练期间的标注修改用于下一次任务。暂停保存训练状态，继续使用同一快照；最终核验阶段可取消。中断任务由管理员手动重试。

训练运行期间，推理 worker 自动降为 1 个 CPU 线程，训练结束后恢复；识别服务继续可用，聊天不被阻塞。

报告包含精确率及其分子分母、召回率、F1、准确率、混淆矩阵、错判图片和耗时。混淆矩阵行表示真值、列表示预测，顺序为"不是该角色／是该角色"。重复使用的测试集标为历史留出评测；留出标签或成员变化后，报告间的分数需要分别评估。指标默认按当前判定阈值重算，见「判定阈值」。

模型通过核验后由管理员启用，可回退上一启用版本。训练期间当前模型继续服务，版本切换前先完成加载和校验。

训练页可选择 224、320 或 448；插件配置 `input_size` 设置默认尺寸，默认为 320。设置用于新训练任务；识别和版本回退使用各模型保存的尺寸。

## 自动识别与测试

收到图片、表情和转发中的图片时，按**该角色自己的判定阈值**（默认 0.60）判定；**同一张图只提示一个角色** —— 在通过各自阈值的角色里取分数最高的一个，若与第二名分差小于 0.02 则认为分不开，整图不提示（这个值经实测校准：0.08 会把 4.6% 的正确高分命中一起丢掉）。单条消息处理预算为 6 秒，超时保留原消息（fail-open）。`auto_recognize=false` 可关闭自动识别。

**聊天捕获**（`chat_capture`，默认关）：打开后，模型在 0.4–0.9 这个「自己也不确定」的区间内的图会被收进训练库，**但不带标签**——它们进「未标注」视图等你确认，确认前不参与训练。每个角色最多积压 100 张，满了停止收集。注意：这会把群成员发的图片保存到本地，开启前请确认对方知情。模型尚未就绪（冷启动中、熔断冷却中、已手动停止）时，该条消息直接不提示，不会阻塞聊天；后台预热完成后后续消息恢复。

识别测试保留最近 24 张图片及结果，可使用当前模型重新识别，显示判断、得分、版本和耗时。聊天图片与测试图片均独立于训练库。

工具接口：

```text
recognize_character_image(message_id, image_index=0, character="")
```

工具读取当前聊天流中指定消息的图片或表情，`image_index` 为零基序号，`character` 留空则返回全部已启用角色的得分。未启用模型、消息或图片失效、索引错误及加载失败时返回具体状态。

判断门槛：得分 ≥ 该角色的判定阈值（默认 0.60）为"命中"，≤ 阈值减 0.2 为"未命中"，其余为"不确定"。得分表示模型输出，不是校准概率，身份仍需结合上下文核对。

## 判定阈值

每个角色有独立的线上判定阈值，默认 **0.60**，存在 `settings` 的 `threshold:<角色>` 键里。它只影响自动提示、工具判定与"错判"列表的成员，**不改变模型权重**；回滚模型也不会重置它。

- 训练报告的「判定阈值」面板会按**验证集**给出建议值：取「精确率 ≥ 90% 的最低阈值」，即同样精确率下召回最大的一点。搜索下限是 0.50 —— 低于它等于在模型自己倾向"不是"时仍判命中。
- 报告同时显示建议值的分子分母与 **Wilson 95% 置信下限**。每类只有 20 组时验证集仅 3/3，`3/3` 的置信下限只有 44%，因此会明确标注「样本不足，仅供参考」，不会显示裸的百分比。
- 支持一键采纳、手动输入、恢复默认（删除覆盖键，而不是写死 0.60）。
- 报告表格里的指标按**当前阈值**重算，每行标注所用阈值；`technical` 中保留训练时 0.50 的原始口径。因此调阈值会让报告数字与"错判"列表同时变化，这是刻意设计：报告要说的是"线上会怎样"。
- 建议值只在验证集上算。测试集是封存证据，用它调阈值会让"留出评测"失去意义。

## 数据存储

持久数据全部写在宿主 SDK 授予的插件数据目录（默认 `data/plugins/org.civetc.char-recog/`），插件源码目录只放只读素材：

- `catalog.sqlite3`：图片、标签、任务和版本记录。`jobs` 表的 `device` / `input_size` 两列供任务列表使用，避免每次轮询都读取快照（旧库自动 ALTER，旧任务首次读取时回填）。
- `settings` 键：`active:<角色>` / `previous:<角色>` / `last_held_truth:<角色>` / `threshold:<角色>` / `eval_built:<角色>` / `characters` / `form_request_key` / `test_history` / `last_test` / `worker_mode` / `worker_override`。
- `uploads/`：宿主上传凭证落点（领取后即入库，不长期保留）。
- `images/`、`thumbnails/`：原图与缩略图缓存。
- `test-images/`：识别测试用图（只保留最近 24 张，超期即删）。
- `jobs/<任务>/`：训练快照、断点、进度与报告。
- `models/<版本>/weights.pt`：角色模型。
- `dependencies/packages/`：依赖覆盖层。
- `dependencies/downloads/`：下载缓存与续传文件。
- `environment-status.json`、`environment.log`、`inference.log`：安装与推理状态、日志。

发布插件时包含源码、页面、声明文件和通用预训练底座。运行数据、环境、配置和日志由各实例保管。

防护点（0.5.21）：`sqlite3.Error`（库锁、IOERR 等）不属于 `ValueError`/`OSError`，此前会从所有兜底里穿过——聊天捕获线程的异常会落在无人消费的 executor future 上完全不可见，WebUI 动作会把裸异常抛给宿主。现在两类路径统一收口：捕获线程异常记 warning 日志，动作错误收敛为 `{"success": false}` 结构。

`tools/migrate_from_maiself.py` 可以把上游 `maibot.mai-recog-self` 数据目录整体迁移过来（整库归属到一个角色、保留划分与模型血统，幂等，支持 `--dry-run`）。运行它需要宿主 Python 或插件覆盖层里已有 Pillow + numpy。

## 数据流向与网络访问

- **不外发任何用户数据**：不使用 `httpx`/`requests`/`aiohttp`，不向第三方上传聊天记录、用户 ID、群号、图片、配置或 token；没有用户可控 URL，因此也没有 SSRF 面。
- **唯一的出站访问**是安装 PyTorch 依赖时的 `download.pytorch.org`（官方索引与官方 CDN），域名在代码里硬编码，不跟随索引返回值取主机。
- 每个 wheel 都用索引提供的 **SHA256 强校验**，校验失败即删除重下；安装包缓存拒绝符号链接、拒绝越出插件目录的路径。
- 安装动作由管理员在 WebUI「运行环境」页显式点击触发，**不会在插件加载时自动联网**。
- 训练与推理的模型权重只读本地文件：ImageNet 底座与已训练模型都做 SHA256 校验后才加载。
- 训练断点（`resume.pt`）用 `torch.load` 恢复，仅由训练 worker 写入，并与 `resume-audit.json` 里的快照摘要 + 文件 SHA256 双向核对；用户上传的图片永远不会成为反序列化输入。

## 验证

测试命令：

```shell
python -m pytest tests
```

缺少 PyTorch 时，3 个需要真实训练/推理的测试模块会自动跳过（`test_cpu_acceptance.py`、`test_input_size.py`、`test_resume.py`），其余用例仍会执行；装上 CPU 版 PyTorch 后这三个模块会真实执行。当前完整环境（含 torch）实测 **214 passed / 1 skipped**。另需 `Pillow`、`numpy`、`psutil`、`pytest`；`test_tool.py` 与 `test_annotation_policy.py` 还需要 `maibot_sdk`（缺失时自动跳过整模块，不会中断收集），其中「默认配置契约」一条另需本地 SDK 的 `src.plugin_runtime` 可导入（在 MaiBot 主程序目录下运行时满足）。

> 这三个模块自 0.3.0 起一直因缺 torch 而跳过，参数错误被掩盖到 0.4.1 才修。**改完训练链路务必在有 torch 的环境跑一次全量**，否则门禁只覆盖一半。

`test_webui_contract.py` 是静态契约测试，不需要任何三方依赖：它校验 `webui.json` 声明的 action 参数与 `webui/index.html` 里 `operate(...)` 的实参一致、生成产物与共享源同步。

页面不再声明同一套 action：宿主要求每页最多 20 条，所以每页只带自己区块能触发的动作，测试相应改为「每页覆盖本页触发面 + 并集覆盖全部调用点」。另有 `test_webui_host_limits.py` 固化宿主文档里的全部限额（页面数、每页 action/query 上限、参数数、`uploads` 必须绑定接收必填 `upload_id` 的 action、页面体积），这些限制违反任意一条都会让整份声明作废、插件直接不加载。

`test_scores.py` / `test_thresholds.py` / `test_source_index.py` / `test_jobs_columns.py` / `test_annotation_policy.py` 均为 torch-free：分别覆盖阈值数学与建议值、角色级阈值存储、`SourceIndex` 与旧线性扫描的等价性（含随机化对照）、`jobs` 表迁移与快照回填、以及「只提示一个角色」的聚合策略。

实测结果见 [VALIDATION.md](VALIDATION.md)，合成素材测试用于验证工程流程，实际识别效果由训练数据决定。

## 与上游的差异

相对 SengokuCola/MaiSelfPlugin，本插件做了这些改动（上游原文不再保留，避免与实现不一致）：

| 项 | 上游 | 本插件 |
|---|---|---|
| 识别目标 | 单角色（"是不是 Bot 自己"） | 每角色一个二分类模型，`characters` 可增删 |
| 配置键 | `character_name`（单角色） | `characters`（角色名单）+ `input_size` + `worker_python` |
| 工具名 | `recognize_self_image(message_id, image_index=0)` | `recognize_character_image(message_id, image_index=0, character="")` |
| 判定文案 | "是自己／不是自己" | "命中／未命中／不确定" |
| 数据库 | 无角色维度 | `images`/`jobs`/`models` 增加 `character` 列，旧库自动 ALTER 迁移 |
| WebUI | 单角色页面 | 头部角色选择器，5 页按角色隔离查询与操作 |
| 依赖管理 | 插件目录内 `.venv` | 共享覆盖层（数据目录内）+ 可选自定义环境 |
| 数据目录 | `data/plugins/maibot.mai-recog-self/` | 宿主授予的 `ctx.paths.data_dir` |

未复制上游的任何个人图片、标签库、实验结果或已训练的身份模型；`assets/mobilenet_v3_small-047dcff4.pth` 是 PyTorch 官方 ImageNet 权重。
